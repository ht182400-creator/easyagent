### 日志体系（本轮建立，长期有效）

| 类型 | 位置 | 生成方式 |
|------|------|---------|
| 运行日志 | `logs/runtime/easyagent-YYYY-MM-DD.log`（每日轮转 / 保留 30 天） | 运行时自动 |
| 测试日志 | `logs/test-logs/<日期>_<时间>_<范围>/` | `pnpm test:log` |
| 命令输出 | `logs/build-logs/<日期>_<时间>_<标签>.log` | `pnpm log --label X -- <命令>` |

**"为什么看不到 debug 日志"的三层答案**：
1. 控制台默认 `info` 级别 → DEBUG 不打印（设计如此，保持清爽）；
2. 文件此前**根本没有**（已修，文件默认 `debug` 级）；
3. 代码里本来就几乎不调用 `logger.debug`（已补 AgentEngine 入口/出口/轮次/工具执行 + 安全中间件判定点）。

**纪律**：日志一律写 `logs/`（项目内），禁止系统临时目录、禁止随手重定向到 `temp/`。

## [测试:工具] 新增的质量门禁与日志工具（长期复用）

| 脚本 | 用途 |
|------|------|
| `scripts/run-tests-log.mjs` | 全量回归 + 分层测试日志（文件全量级别 / 控制台按需过滤） |
| `scripts/verify-data-consistency.mjs` | 测试数据单一真源门禁（只校验不写文件，避免钩子自污染） |
| `scripts/verify-css-tokens.mjs` | 设计令牌一致性门禁（已用负向探针自测有效性） |
| `scripts/run-logged.mjs` | 任意命令输出存档到 `logs/build-logs/` |
| `scripts/verify-runtime-log.mjs` | 验证运行日志是否真的落盘且含 DEBUG |

**踩坑记录**：`run-logged.mjs` 初版用 `process.exit(main())`，导致异步路径下进程立即退出、子进程根本来不及跑——表现为"日志只有头部、命令没执行"。已修正并把该陷阱写进代码注释。
