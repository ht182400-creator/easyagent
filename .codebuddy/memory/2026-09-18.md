## [P1-4:安全+UX] 前端 Markdown 渲染加固：修掉 2 个 XSS 缺口 + 补上表格/代码高亮

### 发现的两个真实 XSS 缺口（原自研正则渲染器）
```ts
// 原本只转义 & < >，漏了 "，且 URL 协议完全不过滤
let html = text.replace(/&/g,'&amp;').replace(/</g,'&lt;').replace(/>/g,'&gt;');
html = html.replace(/\[([^\]]+)\]\(([^)]+)\)/g, '<a href="$2" ...>$1</a>');
```
| # | 缺口 | 攻击样例 |
|---|------|---------|
| ① | `"` 未转义 → 属性逃逸 | `[链接](x" onmouseover="alert(1))` |
| ② | **URI 协议完全不过滤** | `[点我](javascript:alert(1))` **点击即执行**（比 ① 更直接） |

另发现：`PluginsMarket` 把 **GitHub 远程 README 裸 HTML** 直接塞进 `dangerouslySetInnerHTML`，**完全无消毒**；
且它用的 `prose prose-invert` 依赖 `@tailwindcss/typography`，而**项目并没装** → README 一直无排版（与 P0-5 令牌断裂同类病灶：引用不存在的定义且不报错）。

### 选型理由
- **markdown-it**（`html:false` 默认转义 + 原生表格 + v15 自带类型）而非 marked
- **highlight.js** 而非 shiki：markdown-it 的 `highlight` 钩子是**同步**的，shiki 需异步加载 WASM → 得不偿失
- **DOMPurify** 只用于远程 HTML；本地 Markdown 不重复消毒（聊天列表虚拟滚动高频渲染，没必要）

### 测试：35 条（含 6 条 🛡️ 安全回归）

## [P1-4 续:安全] 消除远程 HTML 信任面：服务端 README 改取原始 Markdown

- **问题**: v0.6.29 把「裸 HTML 无消毒」修成「DOMPurify 事后消毒」，但本质仍是**先引入危险内容再过滤**
- **修复**: 服务端改 `Accept: application/vnd.github.raw` 取原始 Markdown；前端与聊天共用 `renderMarkdown()`
- **状态**: ✅ 完成并发布 v0.6.30

### 改动
| | 旧 | 新 |
|---|---|---|
| Accept | `vnd.github.html+json` | **`vnd.github.raw`** |
| 方法 | `getReadmeHtml()` | `getReadmeMarkdown()` |
| 返回 | 裸 HTML | **原始 Markdown** |
| 前端 | `sanitizeHtml()` 消毒 | `renderMarkdown()` 同一条路径 |

连带：`PluginMarketService` 字段 `readmeHtml` → `readmeMarkdown`；前端 `PluginDetail` + `PluginsMarket.tsx` 同步。
**`sanitizeHtml()` 与 `dompurify` 依赖一并移除**（已无调用方）。

### 真实 API 实测（关键：这个改动的成立前提）
```
raw  → "# EasyAgent - AI编程助手 v0.4.0 (Gemini)\n\n> 集成中国主流大模型的全功能AI编程助手…"
html → "<div id=\"readme\" class=\"md\" data-path=\"README.md\"><article …><svg …>…"
```
对照可见旧路径取回的是带**内联 SVG / data-path / itemprop** 的臃肿 HTML —— 而它此前被直接塞进 `dangerouslySetInnerHTML`。

### 三重收益
1. **信任面被消除而非过滤** —— 不存在"远程 HTML 进 DOM"这一步
2. README 获得表格 / 有序列表 / 代码高亮
3. 移除 `dompurify`，Web JS **741 KB → 711 KB**

### 测试调整
- 服务端插件市场改断言 `readmeMarkdown`（含「不得含 `<h1>`」护栏）
- 前端删 7 条 `sanitizeHtml` 消毒用例 → 新增 4 条「远程不可信 README」回归
- 测试文件从 jsdom **改回 happy-dom**（DOMPurify 已移除，无需特殊环境）

### ⚠️ 又踩了一次自己记录过的坑
新用例用 `pnpm add x` 作 bash 样例 → 无 hljs token → 断言失败。
**正是 v0.6.29 已记录过的坑**：写高亮断言时样例必须符合该语言语法（`echo`/`ls` 才有 token）。
→ 该坑值得长期警惕，已在 MEMORY.md 的陷阱表里保留。

### 验证
服务端插件市场 ✅ 50/50 · Markdown 模块 ✅ 32/32 · **全量回归 ✅ 1672/1672，0 失败**
类型检查 ✅ 0 诊断 · Web 构建 ✅ 退出码 0 · 产物中 dompurify **0 处命中**

## [P1-2 之二:模型目录] 目录自动化 + 多源降级（回答「连不上 GitHub 怎么办」）

- **问题**: ① 厂商发新模型能否自动升级 ② 连不上 GitHub 怎么办
- **状态**: ✅ 完成并发布 v0.6.33（方案见 `docs/69`）

### 关键发现（与直觉相反）
**客户端"自动拉取"早就实现了**（远程 + CDN 兜底 + 24h 缓存 + 三级降级 + 手动刷新）。
断的是**中间那环**：
> `models-catalog.json` 的 `generatedAt` = **2026-06-19**，**91 天**没重新生成过。
> 客户端每天勤快地自动下载一份**三个月前**的数据 —— **"自动拉取"有了，"自动升级"并没有**。

原因：目录文件**人工维护**（无生成脚本、无定时任务）。原降级链只有 GitHub raw + jsdelivr，
**国内两者都常不可达**，且失败**没有任何提示**。

### 核心洞察：把两类数据分开
| 数据类型 | 最佳通道 |
|---|---|
| **模型列表**（有哪些模型） | ⭐ **厂商 `/models` 直连**（国内可访问，且"厂商一发就有"） |
| **模型元数据**（价格/上下文/能力） | 目录分发（CI/社区维护） |

→ 所以正确策略不是"找更多 GitHub 镜像"，而是**让更新通道不依赖 GitHub**。

### 交付
**① 目录自动生成** `scripts/refresh-models-catalog.mjs`（`pnpm models:refresh`）
- 预设为基准（元数据已校准）+ 厂商 `/models`**仅用于发现新模型**
- 合并规则：只增不删 / 不覆盖已校准元数据 / 新增标 `unverified`
- CI 定时每周一自动重新生成并提交（`.github/workflows/refresh-models.yml`）

**② 多源降级链**：
`自定义 URL → 本地文件 → 额外镜像 → GitHub raw → jsdelivr → 本地缓存 → 应用内置`
- 新环境变量：`EASYAGENT_MODELS_CATALOG_URL` / `_FILE` / `_MIRRORS`
- **原则：绝不让"连不上"变成"没有模型可选"** —— 缓存永不作废，只告警

**③ 厂商直连补齐**：目录 stale 或来自缓存/内置时，用已配置 Key 的厂商直连 `/models` 并**入**目录

**④ 状态可见**：`/api/providers/catalog/status` 返回 `source` / `stale` / `ageDays` / `maxAgeDays`

### 顺带修掉 flaky 测试
`plugin-sandbox` / `plugin-manager` 全量并行下 **11 条间歇性失败**（单独跑 96/96 全过）
→ 跨文件状态干扰（插件系统持进程级单例）。处置：core 设 `fileParallelism: false`。
**代价真实：core 15s → 35.9s（+140%）**。属**预防性**修复（未能稳定复现）。
→ 教训：**"只在并行的负载下失败、单独跑必过" = 跨文件状态干扰的典型特征**。

### 过程中又被测试抓到一个缺陷
`seedCatalog` 把同一 `providers` 数组引用反复注入，前序用例的 `mergeModels` 变更
污染了后续用例（"幂等"用例误报）。**共享可变 fixture** → 修法是深拷贝注入。

### 验证
目录生成 ✅ 11 家/52 模型（原 40）· 过期检测 ✅（修复前报 91 天 FAIL）
多源降级端到端 ✅ 5/5 · 单元测试 ✅ 16/16 · **全量回归 ✅ 1696/1696**
**`pnpm verify:all` ✅ 7/7**（新增"目录新鲜度"+"目录多源降级"两项）

1. 自动发现的新模型**元数据是保守默认值**（标 `unverified`），准确值仍需人工/官方校准
2. 发布为 npm 包走 npmmirror（国内最稳）**需 npm 发布权限**，未做
