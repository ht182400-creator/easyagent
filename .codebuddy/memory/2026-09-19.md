## [F16:沙箱] 用户报障：`node -e 'console.log(1+1)'` 被拒 / `node -e console.log abc` 无输出（10:45）

- **现象**: ① 命令被「不安全的 shell 元字符」拒绝 ② 去掉括号后能跑，但退出码 0、无任何输出
- **根因**: **同一个根因** —— `LocalSandbox.containsShellMetacharacters` 的黑名单 `/[;&|`$()><#…]/` 把 `(` `)` 一律当子 shell，忽略了**引号内是字面量**；于是任何带函数调用的 JS 单行代码（必须写括号）都被拒。用户去掉括号后命令合法但语义变了：`node -e console.log abc` 只求值表达式 `console.log`（不调用函数）→ 无输出、退出码 0，属**正确结果**
- **附带发现（真 bug，未修）**: `LocalSandbox.exec` 的 `proc.on('close')` 里 `if (killed) return;` → **超时被 kill 后 Promise 永不 settle**，请求会一直挂着（UI 的「超时 30s」形同虚设）
- **UI 缺陷**: `success:true` + stdout 为空时无「无输出」提示，容易被误判成"结果不对"
- **状态**: ⏸ 未修（用户仅问「为何结果不对」）；修复方案 A=只在引号外检测元字符；B=不走 shell，直接 argv `spawn(cmd, args, {shell:false})`（推荐，注入从结构上不可能）

## [F29:性能] 语义扫描 11s → 0.14s（O(n²) 根治）（13:45）

- **用户质疑**: 「300 文件扫描为何要 11s」→ 剖析发现耗时极度不均：**一个压缩单行的 vendored 插件 bundle 占 96%**（10.35s / 25804 处符号匹配），其余 299 文件合计 380ms

- **修复**: `buildLineIndex()`+二分查找（行号/列号 O(1)）、签名用 `indexOf(from)`+窗口、`looksMinified()` 跳过压缩产物、`MAX_SYMBOLS_PER_FILE=3000`、忽略 `.obsidian`/`vendor`、默认上限 300→**1000**
