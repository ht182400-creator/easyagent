## 一、机制

**脚本**：`scripts/perf-baseline.mjs`（一体两用）

```bash
pnpm bench:baseline   # 测量并写入 benchmarks/baseline.json（基线过期时重建）
pnpm bench:check      # 测量并与基线比对（CI / verify:all 用）
```

| 指标 | 测量方法 | 说明 |
|------|---------|------|
| `startupMs` | spawn 真实 server dist → 轮询 `/api/health` 首次 200；**3 轮取中位数** | 进程调度噪声大，用独立宽容档（告警 40% / 失败 80%） |
| `healthRttMs` | 启动后稳态采样取最小；中位数 | 亚毫秒级时基线为 0，百分比无意义 → 跳过比对只报绝对值 |
| `toolSchemaTokens` | 复用 core `estimateToolDefinitionsTokens`（与 `measure:context` 同口径） | 工具 schema/描述膨胀的守门指标 |
| `tokenPerTask` | **null**（需真实 provider key） | 本地 `pnpm benchmark` 跑出后人工补录 |

**回归判定（CI）**：一般指标劣化 **>20% 告警**（GitHub `::warning::`，不阻断）、**>50% 失败**（exit 1）。

**接入点**：
- `verify-all`（key=`perf`，需先构建 server；无基线时 SKIP）
- `ci.yml` smoke-test job 尾部（构建→冒烟→基线检查 一气呵成）

**基线快照（v0.6.40，本机）**：`startupMs=714 · healthRttMs=1 · toolSchemaTokens=8774`

## 二、使用纪律

1. **有意变更（加工具/改启动逻辑）后**：跑 `pnpm bench:baseline` 重建基线并在 commit 里注明；
2. **意外劣化（门禁告警）时**：先查根因，修不掉再评估是否接受 → 接受才重建基线；
   **禁止"先重建基线让它闭嘴"** —— 那等于拆掉警报器；
3. 基线文件随仓库走，比对时打印双方 commit —— 跨机器/跨平台噪声需注意
   （CI 与本地环境不同，告警要结合 runner 环境解读）；
4. 门禁已做**负向验证**：注入劣化基线后正确 FAIL（exit 1）—— 不是假安全网。
