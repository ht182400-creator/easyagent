## 一、为什么先建"安全网"再动刀

3827 行、93 条路由的纯搬迁式重构，最大的风险不是"改错逻辑"，而是**静默丢路由**：
现有集成测试只覆盖一部分，漏掉的部分不会报错，直到线上 404 才被发现。

因此**第一步不是搬代码，而是建立可证明等价的手段**：

| 安全网 | 作用 | 位置 |
|--------|------|------|
| **路由清单快照测试** | 用 Express 内部注册表枚举全部路由，与基线逐条比对；**丢失与新增都会失败** | `packages/server/src/__tests__/route-inventory.test.ts` |
| **路由枚举工具** | 把 `app.all()` 展开的 35 个 HTTP 动词归一化为 `ALL`，让清单可读 | `packages/server/src/utils/routeInventory.ts` |
| **运行时行为验证** | 单测覆盖不到的**注册顺序**与**路径基准**约束，真实启动发请求验证 | `scripts/verify-server-routes.mjs` |
| **TypeScript 类型检查** | 依赖注入漏字段必然编译失败（搬迁时最实用的机械保证） | 语言服务器 / IDE |

### 1.1 建立安全网时的两个实测发现

1. **`app.all('/api/*')` 会展开成 35 条记录**。Express 内部把 `route.methods` 填成全部 HTTP 动词
   （`ACL`/`BIND`/`M-SEARCH`…），若不归一化，一条 404 兜底会在清单里占 35 行，淹没真实差异。
2. **基线首跑就修正了两处误判**：① `app.get('*')`（SPA fallback）是合法路径，
   断言"必须以 `/` 开头"过严；② 语言服务器诊断比根 `tsconfig` 更可信 ——
   根 `tsconfig.json` 的 `exclude` 含 `packages`，跑它其实**什么都没检查**（`TS18003: No inputs were found`）。

### 1.2 更新基线的方式

```powershell
$env:UPDATE_ROUTE_INVENTORY='1'; pnpm --filter @easyagent/server test
```

**⚠️ 更新后必须 review 基线文件的 diff** —— 确认每一处增删都是有意为之的接口变更。

## 二、拆分原则

| 原则 | 说明 |
|------|------|
| **纯搬迁** | 路由路径、方法、处理逻辑、**注册顺序**全部保持不变 |
| **显式依赖注入** | 每个模块声明自己的 `XxxRoutesDeps`，**不引入"上帝上下文"**（避免一个巨大 `ServerContext` 变成新的耦合中心） |
| **顺序约束显式化** | 如 `registerStaticRoutes` 必须最后调用，约束写在模块头注释与调用点注释里 |
| **`__dirname` 由调用方传入** | 路径基准取决于**构建产物布局**而非源码布局；从源码文件里取会让"拆文件"意外改变路径解析（极难定位） |

### 3.2 为什么选这三段

它们是**连续的三段**（原 2916–3377 行）且依赖面清晰，可以一次搬迁、一次验证，
把风险集中在一次可回滚的改动里；同时覆盖了最容易出事的**静态托管与顺序敏感逻辑**，
从而验证整套拆分方法论是否成立。

### 3.3 关键顺序约束（模块内已保留）

```
knowledge 内部：/stats/summary  必须先于  /:id
                （否则 :id 会把 'stats' 当成文档 ID 捕获）

静态托管整体：  /api/* 404 兜底  →  /doc-viewer  →  静态资源  →  app.get('*') SPA fallback
                （顺序错误会让未匹配的 API 返回 200 + index.html，
                  前端把 HTML 当 JSON 解析，报出与根因无关的错误）
```

### 5.2 第三批实测记录（v0.6.38）

- **净减 928 行**（3074 → 2146），是三批中减幅最大的一批（config 段含 ~450 行模型获取/合并逻辑）
- **两个跨段共享的符号，处理方式不同**：
  - `marketService`：全局单例（WebSocket 段持同一实例广播安装进度）→ **创建留在 index.ts，
    以 deps 注入**；两个「市场 ↔ PluginManager」接联回调随模块注册
  - `fetchModelsFromProvider`：被 config 路由**和 index.ts 启动初始化块**（厂商直连补齐）同时消费
    → **提为 routes/config.ts 的模块级导出**，index.ts 导入使用 —— 两处必须共用同一实现
- **随迁的"孤儿"辅助**：`DEFAULT_TEMPLATES`、`formatOllamaModelName`、自定义技能磁盘存储
  （`loadCustomSkills`/`saveCustomSkills`）、`getAllSkillsWithStatus`、局部 `ModelInfo` 接口
- **⚠️ 本批的方法论教训：大块删除不要依赖"首个 `{` 配对"的脚本**
  —— `Array<{...}>` 类型注解会让括号平衡提前归零，截断删除后残留**语法合法但行为错误**的
  代码（`return` 裸露在 createApp 顶层会提前退出！语言服务器未必立刻报错）。
  靠**逐符号残留核查**（迁移后对每个被搬走的符号做全文计数）才抓出来。
  结论：**块级搬迁必须做残留核查 + 快照测试双重验证**，二者缺一不可
- **验证**：路由快照比对（93 条逐条一致）· server 265/265 · 全量 1729/1729 ·

### 5.3 第四批（system 部分）实测记录（v0.6.39）

- **净减约 470 行**（2146 → 1672），`routes/system.ts` 承接系统(5) + Token 用量(1) + 北极星(3) 共 9 条路由
- **TDZ 陷阱被"理论命中"**：`/api/test/open-panel` 依赖 WS 段的 `wsSubscriptions`（const）。
  旧代码把引用写在**回调里**（请求时才执行）所以没事；注册式搬迁让引用**立即求值** →
  `ReferenceError: Cannot access 'wsSubscriptions' before initialization`。
  解法：`wsSubscriptions` 定义**上移**到系统段之前（`safeSend` 是函数声明有提升，无需动）。
  **教训：拆出的路由若引用"定义在后"的 const，注册即炸 —— 语言服务器不报 TDZ，测试才会**
- `APP_VERSION` 解析块保留在 index.ts（入口段也用），以 `deps.appVersion` 注入；
  `serverDir` / `port` 一并注入（路径与端口都是构建/启动期事实）
- **验证**：server 265/265 · 全量 1729/1729 · `verify:all` 8/8 · tsup 退出码 0

1. 读该段落，抽 `RoutesDeps`；
2. 写模块 + 替换为注册调用；
3. 跑 `pnpm --filter @easyagent/server test`（路由快照 + 集成测试）；
4. 跑 `pnpm verify:server-routes`；
5. 语言服务器确认 0 诊断；

**目标**：`index.ts` 最终收缩到 **≤500 行**（仅保留：初始化各管理器 → 组装依赖 → 注册路由 → 返回服务对象）。

## 六、经验与陷阱

| # | 经验 | 说明 |
|---|------|------|
| 1 | **先建安全网，再动刀** | 快照测试在建立过程中就抓出 2 处误判（`app.all` 的 35 动词展开、`*` 路径断言过严），若没有它，这些噪声会混进重构判断 |
| 2 | **根 `tsconfig.json` 不检查 `packages/`** | 其 `exclude` 含 `packages`，跑它得到的是 `TS18003: No inputs were found` —— **看起来"0 错误"其实是空跑**。类型检查应以语言服务器诊断或包级 `tsconfig` 为准 |
| 3 | **`__dirname` 不要在新模块里取** | 它取决于构建产物布局；拆文件后源码目录层级变了，取值可能随之改变。由调用方传入最安全 |
| 4 | **注册顺序要用注释显式固定** | 顺序约束是"看不见的契约"，搬迁时最容易被破坏。已写在模块头 + 调用点两处 |
| 5 | **路由快照要双向比对** | 只查"丢失"不够，还要查"新增" —— 意外新增（如重复注册）同样是 bug（快照测试另有重复注册断言） |
