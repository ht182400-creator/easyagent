## 一、机制设计

### 1.1 版本戳：`PRAGMA user_version`

SQLite 内建、存在数据库头、随事务一起提交 —— 无需额外迁移记录表：

```ts
import { DatabaseMigrator } from '@easyagent/core';

new DatabaseMigrator(db, { name: 'sessions', migrations: SESSION_MIGRATIONS }).migrate();
```

| 特性             | 说明                                                                                                                                                  |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| **事务化**       | 每个迁移的 `up()` 与 `user_version = N` 推进在同一事务内；迁移抛错整体回滚，版本不推进                                                                |
| **断点续跑**     | 下次启动自动从当前版本继续，已应用的迁移不会重复执行                                                                                                  |
| **fail-fast**    | 迁移失败向上抛（宁可功能不可用，不带着未知 schema 写库）                                                                                              |
| **只前进不回滚** | 无 down 迁移（本地应用回滚脚本是伪安全——旧代码读到新字段同样出错），回滚 = 恢复备份                                                                   |
| **环境探测**     | 若驱动查不到 `user_version`（返回 `null`）→ 记 debug 并**整体跳过迁移**，不猜版本硬跑（现为防御路径：测试已改用真实库，不再有"pragma 无感知"的 mock） |

### 1.2 基线迁移的幂等铁律

迁移机制引入时，**所有存量库都是 user_version=0**。因此 v1 基线必须兼容：

- `CREATE TABLE IF NOT EXISTS`（表已存在 = 无操作）
- 缺失列用 `addColumnIfMissing()` 补（内部 `PRAGMA table_info` 判存后 `ALTER TABLE ADD COLUMN`）
- **禁止**裸 `CREATE TABLE` / 裸 `ALTER TABLE`

### 1.3 新增迁移的规则（改这块前必读）

1. 追加到清单**末尾**，`version` = 上一条 + 1；
2. **永不修改历史条目** —— 已随版本发布的迁移视为不可变（改历史 = 存量库与代码版本错位）；
3. 构造时校验版本号从 ≥1 开始严格递增，乱序/重复直接抛错（断点续跑语义依赖单调性）。

### 测试环境注意（重要）

- **测试使用真实数据库**：`core` 的 vitest 不再把 `better-sqlite3` 别名到内存 mock
  （2026-09-19 移除）——旧 mock 的 `pragma()` 是空操作，会让迁移在测试中被**静默跳过**、
  真 SQL 语义从未被验证；现在每个用例用真实库文件（系统临时目录，afterAll 清理）。
- **两个驱动都要过**：`core/src/__tests__/sqlite-driver.test.ts` 用**参数化**方式把同一组断言
  分别打在 `better-sqlite3`（默认）与内置 `node:sqlite` 上；后者需 Node ≥ 22.5，低版本**显式 skip**。
  跑内置驱动：`EASYAGENT_SQLITE_DRIVER=node pnpm test`。
- 迁移器专项测试里 `createRequire` 直连原生模块的写法**保留**（用于把原生驱动固定为语义基准）。
- Windows 下动态 `import(绝对路径)` 必须用 `pathToFileURL()` 转 file:// URL（脚本实测踩坑）。
