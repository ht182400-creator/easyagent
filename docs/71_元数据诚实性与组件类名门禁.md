# 元数据诚实性（`unverified`）与组件类名门禁

> **建立日期**: 2026-09-18
> **当前状态**: ✅ 已完成并发布 —— 两项均落地并有测试/门禁守护
> **起因**: v0.6.33 引入 `unverified` 字段后**界面从未呈现**；补 UI 时**又发现一类复发了三次的静默失效**

---

## 一、`unverified`：让"不知道"显示为"不知道"

### 1.1 问题

v0.6.33 的「厂商 API 直连」通道会厂商 `/models` 发现新模型。但该端点**只返回模型 ID**，
不含价格、上下文、能力等元数据。于是新模型被填入**保守默认值**：

```ts
maxContextTokens: 32768, maxOutputTokens: 8192,
supportsTools: true, supportsVision: false,
pricing: { input: 0, output: 0 },   // ← 危险
```

并标记 `unverified: true`。

**但界面从未区分呈现。** 后果是**主动误导**：

| 显示      | 用户读作         | 实际           |
| --------- | ---------------- | -------------- |
| `¥0 / ¥0` | "免费"           | 我们不知道价格 |
| `32K ctx` | 真实上下文是 32K | 我们不知道     |
| 🛠️        | 支持工具调用     | 我们不知道     |

> 这与本项目此前的原则一脉相承：**宁可显示"未知"，也不要显示一个自己都不信的数值。**

### 1.2 断点定位（链路排查）

排查发现字段在**服务端边界**被丢弃：

| 环节                                |          状态           |
| ----------------------------------- | :---------------------: |
| `ModelRegistry.mergeModels()`       |  ✅ 设置 `unverified`   |
| `ConfigManager.mergeRemoteModels()` | ✅ 整对象 spread，保住  |
| 服务端 `formatPresetModel()`        | ❌ **逐字段挑选**，丢掉 |
| `/api/providers` 的 models 映射     |       ❌ 同样丢掉       |
| 前端类型                            |    ❌ 压根没有该字段    |

**根因**：服务端响应体是**逐字段重新映射**的（不是整对象透传），新增字段必须在映射处显式加上 ——
否则会在无声无息中丢失。

### 1.3 修复

**服务端**：`formatPresetModel` / `/api/providers` / `/api/providers/all-models` 三处补透传；
core 的 `ModelInfo` 也显式声明 `unverified?: boolean`（不依赖结构化类型的偶然兼容）。

**前端**（`Providers.tsx` 提供商页 + `ChatInput.tsx` 模型下拉框）：

| 元素     | 未校准时的呈现                                                             |
| -------- | -------------------------------------------------------------------------- |
| 徽章     | `⚠️ 未校准`（`badge-warning`），悬停给出完整解释                           |
| 上下文   | `~32K ctx` —— **`~` 明确标出这是默认值**，悬停说明"保守默认值，非真实规格" |
| 价格     | **不显示 `¥0/¥0`**，改为"价格未知"                                         |
| 能力图标 | 旁附 `⚠️`，提示能力字段同样未校准                                          |

### 1.4 测试（3 条，`provider-config-api.test.ts`）

锁住透传链路 —— 因为它是**逐字段映射**，极易在后续改动中被静默丢掉：
① `/api/providers` 透传；② 类型必须为布尔或未定义；③ `/api/providers/all-models` 同样透传。

## 二、组件类名门禁：堵住一个**复发三次**的病灶

### 2.1 又是同一类问题

改 UI 时顺手核实了徽章类名，发现：

```
源码使用：badge-green(4) / badge-yellow(1) / badge-blue(1)
CSS 定义：badge-success / badge-warning / badge-error / badge-info / badge-neutral
```

**6 处徽章一直在无样式裸奔。**

这已是同一病灶的**第三次**：

| 时间    | 现象                                                        | 后果                           |
| ------- | ----------------------------------------------------------- | ------------------------------ |
| P0-5    | `tailwind.config.js` 引用未定义的 CSS 变量                  | 样式静默失效，被父级色兜底掩盖 |
| v0.6.29 | 用了 `prose prose-invert`，但未装 `@tailwindcss/typography` | README 长期无排版              |
| v0.6.36 | `badge-green` 等 6 处类名不存在                             | 徽章无样式                     |

**共同点：写错类名不报错，只是"看起来有点不对"。** 三次都是偶然发现，不是被检出的。

`verify-css-tokens.mjs` 只覆盖 Tailwind 令牌类名，**不覆盖 `index.css` 里手写的组件类** —— 这就是缺口。

### 2.2 门禁实现

新增 `scripts/verify-component-classes.mjs`（`pnpm verify:classes`，已登记进 `verify:all`）：

1. 解析样式文件，收集全部已定义类名
2. 扫描源码中 `className` / `class` 字面量，提取**受保护家族**的类名使用
3. 报出"被使用但未定义"的类名 + 所在文件，退出码 1

### 2.3 为什么用**显式家族列表**而不是自动派生前缀

自动派生会踩坑：CSS 里定义了 `.overflow-overlay`，就会顺带把 `overflow-hidden`、
`overflow-y-auto` 这些 **Tailwind 自身命名空间**的类也纳入校验 → **大量误报**。

因此 `COMPONENT_FAMILIES` 只登记**确定由本项目手写维护、且不与 Tailwind 冲突**的家族
（`badge` / `btn` / `tool-call` / `tool-header` / `chat-bubble` / `connection-dot` /
`pulse-dot` / `typing-dot` / `markdown-body`）。

> ⚠️ **新增组件类家族时必须同步登记**，否则该家族不受保护。

### 2.4 门禁做了双向验证

| 验证                                                                | 结果                                                      |
| ------------------------------------------------------------------- | --------------------------------------------------------- |
| 修复后正常运行                                                      | ✅ 46 个已定义类 / 91 个源码文件 / 18 个组件类 → 零未定义 |
| **负向测试**（注入临时文件含 `badge-green`、`btn-outline-primary`） | ✅ **精准抓到 2 个**，给出文件位置，退出码 1              |

> 只验证"能通过"是不够的 —— 必须证明它**真的能失败**，否则就是一道假的安全网。

## 四、沉淀的约定

1. **服务端响应是逐字段映射的** → 新增模型/提供商字段时，必须同时改 `formatPresetModel`、
   `/api/providers`、`/api/providers/all-models` 三处，否则字段静默丢失
2. **不知道就显示"不知道"** → 默认值必须用 `~`、`未知` 等标记区分，不得伪装成实测值
3. **引用样式类名前先确认它存在** → 新家族要登记进 `COMPONENT_FAMILIES`；
   校验用 `pnpm verify:classes`
